# System Design: Arabic Morphology with AraBART

## 1. Problem Statement
This project models Arabic morphology as a sequence-to-sequence generation task.

Input:
- A single Arabic token (or a sentence split into tokens during inference)

Output (per token):
- Structured text fields generated by AraBART:
  - `الكلمة` (surface form)
  - `الصنف الصرفي` (morphological/POS-like category)
  - `الجذر` (root)
  - `الحالة` (declinability state when available)

The model predicts morphology in Arabic text format, then the inference layer parses it to JSON for API clients.

- Raw annotation dataset existed as `MASAQ.csv` (157,676 rows, 19 columns).
- Cleaned seq2seq dataset existed as `morphological_descriptions_cleaned.csv` (6,415 rows, `input/target` schema).
- Entry scripts existed at repo root:
  - `prepare_dataset.py`
  - `split_dataset.py`
  - `train_model.py`
  - `main.py` (FastAPI)
- All scripts used hardcoded absolute Windows paths (`D:/...`) and mixed orchestration with core logic.
- No `src/` package layout, no tests, and no CI workflow.

## 3. High-Level Architecture
Components:
- Data Layer (`src/data`):
  - Ingest raw MASAQ CSV
  - Reconstruct word-level forms from prefix/stem/suffix segments
  - Extract roots (CAMeL Tools when available; heuristic fallback)
  - Build `input/target` training pairs
- Model Layer (`src/models`):
  - AraBART tokenizer/model loading
  - Seq2Seq fine-tuning
  - Inference decoder + field extraction
  - Basic exact-match metrics
- Pipeline Layer (`src/pipelines`):
  - CLI entrypoints for prepare/split/train/eval/infer
- API Layer (`src/api`):
  - FastAPI app with `/health` and `/analyze`
- Utility Layer (`src/utils`):
  - Paths, YAML config loading, logging, deterministic seeding

## 4. Data Flow
1. Raw ingest
   - Read `MASAQ.csv`.
   - Validate required columns (`ID`, `Word_No`, `Segmented_Word`, `Morph_Tag`, `Morph_Type`, `Invariable_Declinable`).
2. Morphological reconstruction
   - Group stem rows by (`ID`, `Word_No`).
   - Concatenate prefix and suffix segments.
   - Rebuild full token `Full_Word = prefix + stem + suffix`.
3. Root extraction
   - Primary: CAMeL analyzer root candidates.
   - Fallback: lightweight Arabic-letter heuristic.
4. Target text generation
   - Build Arabic multiline targets with mapped tags/declinability.
5. Dataset export
   - Save cleaned seq2seq pairs to `morphological_descriptions_cleaned.csv`.
6. Split
   - 80/10/10 train/val/test split with `random_state=42`.
   - Output:
     - `data_ready/train.csv`
     - `data_ready/val.csv`
     - `morph_test.csv` (legacy-compatible default)

## 5. Model Design
- Backbone: `moussaKam/AraBART` (encoder-decoder, Hugging Face Transformers).
- Task framing: conditional text generation from token -> morphology description.
- Tokenization:
  - Input max length: 64
  - Target max length: 128
- Decoding (inference):
  - Beam search (`num_beams=4`)
  - Max generation length: 128

## 6. Training Design
- Trainer: `Seq2SeqTrainer`
- Loss: standard token-level seq2seq cross-entropy from transformer model head.
- Core defaults:
  - `learning_rate=3e-5`
  - `warmup_steps=300`
  - `train_batch_size=16`
  - `eval_batch_size=2`
  - `weight_decay=0.01`
  - `num_train_epochs=6`
  - early stopping patience = 2
- Checkpointing:
  - Save per epoch, keep latest best (`save_total_limit=2`)
  - `load_best_model_at_end=True` on `eval_loss`
- Export:
  - Trainer output dir: `arabart_morph_model/`
  - Deployable model dir: `trained_arabart_morph_model/`

## 7. Inference Design
Input:
- One token or whitespace-separated sentence.

Flow:
1. Split sentence into words.
2. Generate morphological text per word.
3. Parse generated text fields:
   - `الصنف الصرفي`
   - `الحالة`
   - `الجذر`
4. Validate root form with Arabic regex; non-Arabic outputs become `N/A`.
5. Return JSON list of per-word analyses.

## 8. Reproducibility
- Determinism:
  - Seeded random states through `src/utils/seed.py`.
- Config-driven defaults:
  - `src/config/default.yaml`.
- Stable entrypoints:
  - `python -m src.pipelines.prepare_pipeline`
  - `python -m src.pipelines.split_pipeline`
  - `python -m src.pipelines.train_pipeline`
  - `python -m src.pipelines.eval_pipeline`
  - `python -m src.pipelines.infer_pipeline`
- Container support:
  - `Dockerfile` serves FastAPI app via Uvicorn.
- Backward compatibility:
  - Root scripts (`prepare_dataset.py`, `split_dataset.py`, `train_model.py`, `main.py`) remain as wrappers.

## 9. Risks and Tradeoffs
- Domain coverage:
  - MASAQ is Quranic/annotated text; general-domain Arabic and dialectal transfer may degrade.
- Label noise:
  - Root extraction quality depends on analyzer and filtering heuristics.
- OOV behavior:
  - Rare or noisy orthography may produce weak generated tags/roots.
- Generation parsing fragility:
  - Output format is text-based; malformed generations can reduce structured parse quality.
- Resource constraints:
  - Training AraBART can be memory-intensive; CPU-only runs are slow.
